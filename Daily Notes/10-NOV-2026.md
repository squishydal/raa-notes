**Firewall**  
Penjaga lalu lintas jaringan berdasarkan aturan (IP, port, protokol). Contoh: database cuma boleh diakses dari app server lewat port 5432, SSH cuma dibuka untuk IP kantor/VPN, sisanya diblok. Kalau WAF, dia juga memblok serangan web seperti SQL injection dan bot.
**Load balancer**  
Membagi request ke beberapa server. Use case:
- **Deploy tanpa downtime**: server 1 dikeluarkan dari pool (koneksi yang berjalan dibiarkan selesai dulu), di-update, dimasukkan lagi, lalu lanjut server 2. User nggak ngerasa apa-apa.
- **Traffic tiba-tiba naik**: request dibagi rata ke banyak server supaya nggak ada yang kewalahan.
- **Health check**: kalau satu server mati, otomatis nggak dikirimi trafik lagi.
**Reverse proxy**  
Perantara di depan server yang menerima request atas nama server. bukan use case-nya. Use case-nya:
- **Routing berdasarkan path**: `/api` ke backend Node, `/blog` ke WordPress, satu domain banyak service.
- **SSL termination**: HTTPS cukup diurus di proxy.
- **Caching** file statis dan **menyembunyikan IP/struktur server asli**.
**Forward proxy**  
Perantara di sisi klien yang mengirim request atas nama pengguna ke internet. Use case:
- **Kontrol akses di kantor**: blok situs tertentu.
- **Logging**: siapa akses apa dan kapan.
- **Jalur keluar tunggal** untuk server internal yang nggak boleh langsung ke internet (misal cuma untuk `apt update`).
- **Caching** paket yang sering diunduh.
- **Menyamarkan IP klien** dari website tujuan, tapi pemilik proxy tetap bisa melihat dan mencatatnya.

1. **Forward proxy (kantor):** request karyawan lewat Squid dulu. Squid cek apakah situs boleh dibuka, mencatat di log, lalu meneruskan ke internet. Tokoku cuma melihat IP proxy kantor.
2. **Firewall/WAF:** request sampai di gerbang depan Tokoku. Firewall cek IP, port, dan protokol (hanya 80/443 yang terbuka). WAF cek isi request, kalau ada pola SQL injection atau bot, langsung dibuang.
3. **Load balancer:** request yang lolos dibagi ke salah satu dari 3 server yang sehat. Server yang mati (gagal health check) dilewati.
4. **Reverse proxy (Nginx):** di server terpilih, Nginx melihat path `/api/`, mengurus HTTPS, lalu meneruskan ke aplikasi Node di belakangnya. Kalau yang diminta file statis, Nginx langsung melayani dari cache atau disk.
5. **Firewall internal:** aplikasi perlu data, jadi konek ke database. Firewall internal hanya mengizinkan app server ke port 5432. Dari luar, database tidak terlihat.
6. **Balasan** jalan mundur lewat jalur yang sama sampai ke karyawan.
